# T0 evidence: what this repository enforces mechanically

Generated by `.github/project/t0_evidence.py` -- edit the generator, not this file.

**This is not a compliance claim.** No certification is asserted, no MISRA text is present in this
repository (A4/A5 are paywalled), and none of the tables below substitute for a deviation permit or an
independent assessment. What they do say is which parts of the free rule sets are enforced by a build
gate rather than by intention, and where every suppression is written down.

is the honest reading of an empty cell and is the largest gap in this table.

## 3. JPL Power of Ten (D3): enforced, or only intended

| Rule | How it is enforced here |
|---|---|
| 1. No `goto`, `setjmp`, recursion | not checked mechanically -- stated as a convention only |
| 2. Bounded loops | not checked mechanically |
| 3. No dynamic allocation after init | by architecture: `-fno-exceptions -fno-rtti` and no container use in
  `include/`; not a gate |
| 4. Functions fit on one page | not checked |
| 5. Minimum two assertions per function | not checked; the analogue here is `WarningsAsErrors` plus the
  invariant suite |
| 6. Smallest scope for data | `readability`/`bugprone` families are **not** enabled |
| 7. Check return values, validate parameters | partially: `bugprone-*` catches some; refusal paths are
  asserted per capability in `capabilities.rst` |
| 8. Limited preprocessor use | `cppcoreguidelines-macro-usage` is enabled |
| 9. Limited pointer use | not checked |
| 10. Compile with all warnings, then test | `WarningsAsErrors: '*'` plus the 24 project gates |

Two of ten are mechanical, two more are partly mechanical. Writing this table down is the point: "we follow
the Power of Ten" would be a claim about intentions, and the rows above are what can be shown.
